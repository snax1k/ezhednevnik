# Чекки — ежедневник для Android

> Черновик. Пункты с пометкой «предварительно» ещё не утверждены и могут измениться.

## О проекте
Чекки — приложение-ежедневник для Android. Задачи собираются по времени (просроченные, сегодня, завтра, на неделе и так далее), есть календарь, категории, напоминания и повторяющиеся дела. Идея и структура взяты у старого приложения-ежедневника, но дизайн и качество работы должны быть современными.

Название для пользователя — «Ежедневник» (ребрендинг 26.10.2026, `app_name`; отладочная — «Ежедневник (отладка)»). Иконка-маскот осталась. «Чекки» — внутреннее имя проекта: пакет `com.snax1k.chekki`, классы `Chekki…`, папка проекта. Идентификатор пакета менять нельзя: для телефона это будет другое приложение, обновление не встанет поверх, а данные останутся в старом.

## Данные (утверждено)
- Таблицы: `categories`, `tasks`, `subtasks`, `habits`, `habit_checks`, `habit_reminders`, `habit_pauses`, `priority_levels`, `attachments` (`data/db`), схема версии 7. Дата хранится днями от 1970 года, время — минутами от полуночи. У единицы повтора фиксированные коды: менять их нельзя, новые значения — только с новыми кодами.
- Вложения (схема 7, миграция 6 → 7): `attachments` — задача (внешний ключ с `ON DELETE CASCADE`), вид (`AttachmentKind`, фиксированные коды: фото 1, видео 2, аудио 3, файл 4), имя файла в `files/attachments`, имя для пользователя, MIME-тип, размер, длительность, время, `position`. Удаление задачи или вложения удаляет только строку; файлы без строк удаляются при запуске приложения, если им больше часа (`AttachmentStore.cleanupOrphans`) — так «Отменить» успевает вернуть задачу с вложениями (`DeletedTask.attachments`). Копия повторяющейся задачи получает свои строки на те же файлы. В `TaskWithDetails` и `SearchableTask` — `attachments_total`.
- Уровни важности (схема 6, решено 29.10.2026): `priority_levels` — название, цвет флажка (ARGB) и `position` (0 — самый важный). У задачи `tasks.priority` — id уровня, 0 — без приоритета (`PriorityLevels.NONE`). Миграция 5 → 6 создала три уровня с id прежних кодов: 3 «Высокий» `#FF8A7A`, 2 «Средний» `#F5BE6A`, 1 «Низкий» `#7BD49A` (зелёный вместо прежнего синего) — колонка задач не менялась. Новая база получает их же (`insertDefaultPriorityLevels`). Задачи сортируются по `position` уровня (`LEFT JOIN priority_levels pl`), без уровня — в конце; в `TaskWithDetails` и `SearchableTask` — `priority_name`, `priority_color`, `priority_position`. Удаление уровня делает его задачи «без приоритета» (`DeletedPriorityLevel` для «Отменить»), уровней не больше 8 (`PriorityLevels.MAX`). Перенос из старого приложения ставит важность по месту: высокая — первому уровню, средняя — второму, низкая — третьему.

Иконка — код `CategoryIcon` (60 штук, фиксированные коды, как у привычек; 17–60 добавлены 29.10.2026: часть нарисована заново — `ChekkiIcons.Category…`, часть — те же картинки, что у привычек и в интерфейсе: вода, сон, бег, календарь, часы, колокольчик, карандаш…), `is_archived` — архив (схема 5). У шести начальных категорий свои иконки (`DefaultCategories`).

Следующая дата — первая по правилу после даты задачи, но не раньше сегодня (`data/Recurrence.kt`). Копия помнит исходную задачу (`repeated_from_id`): если с исходной снять отметку, копия удаляется, пока её саму не выполнили. Во всех группах, кроме «Сегодня», только невыполненные. «Выполненное»: все выполненные, свежие сверху.

Тестовые задачи — только в отладочной сборке, пока нет экрана добавления: `src/debug/.../SampleTasks.kt`, в `src/release` пустая заглушка. Чтобы получить тестовые задачи заново, очистить данные приложения.
- Привычки: `habits` (название, иконка — код `HabitIcon`, номер цвета, `daily_target`, дни недели битовой маской как у повтора, порядок, архив) и `habit_checks` — одна строка на привычку и день (`count` не больше `target`, `target` — цель того дня). Привычки на день выбираются запросом по биту дня недели (`DayOfWeek.bit`). `habit_reminders` — времена напоминаний (привычка + время, минуты от полуночи).
- Паузы привычек: `habit_pauses` — периоды `start_date` (включительно) … `resume_date` (день, с которого привычка снова действует, не включительно; null — без срока). «На паузе до 30 окт» значит, что 30-го она уже снова наверху. Прошедшие паузы хранятся: дни паузы считаются как дни не по расписанию (серию не рвут, выполненный день паузы серию продолжает), и серии в прошлом считаются так же. «Продолжить» в день начала паузы удаляет её, позже — ставит `resume_date` на сегодня.
- Начальные данные после пересоздания базы (теперь только для старых тестовых баз версий 1–4): Room 2.8 вызывает `onDestructiveMigration` между удалением старых таблиц и созданием новых, поэтому `InitialDataCallback` только запоминает это и заполняет базу в `onOpen` (иначе обновление схемы роняет приложение — нашлось на переходе 1 → 2). Тестовые привычки отладочной сборки — `src/debug/.../SampleHabits.kt` (пять на каждый день и «Бассейн» по выходным).

## Уведомления о задачах (шаг 1 сделан, `reminders/`; напоминания привычек — в разделе «Статус»)
- Один системный будильник на задачу (`AlarmReminderScheduler`). Время срабатывания считает `reminderTrigger()` (`ReminderTime.kt`): время задачи минус N минут, у задачи на весь день — от 09:00, в часовом поясе телефона.
- Репозиторий сообщает планировщику об изменениях: новая задача → будильник; отметка «выполнено» → будильник снят и уведомление убрано, у копии повтора — свой будильник; снятие отметки → будильник снова, копия снята.
- По будильнику `ReminderReceiver` перечитывает задачу и показывает уведомление, только если она не выполнена и время напоминания не менялось. Нажатие открывает приложение. Канал «Напоминания о задачах», значок — белая галочка `ic_notification`.
- `RescheduleReceiver` ставит все будущие будильники заново после перезагрузки, смены времени или часового пояса, обновления приложения и когда разрешили точные будильники. То же делается при каждом запуске приложения.
- Разрешения: `POST_NOTIFICATIONS` спрашивается, когда в панели выбирают напоминание; если уведомления выключены — под строкой «Напоминание» подпись и кнопка «Включить» (настройки уведомлений приложения). `SCHEDULE_EXACT_ALARM` — при первом сохранении задачи с напоминанием один раз окно «Напоминания вовремя» с кнопкой в «Будильники и напоминания»; без разрешения будильники неточные (Android может задержать до часа). `USE_EXACT_ALARM` не используем: Google Play разрешает его только календарям и будильникам.
- Проверено на эмуляторе (API 37): запрос разрешения при выборе напоминания, окно про точные будильники и переход в настройки, будильники становятся точными сразу после разрешения, уведомление приходит минута в минуту, после перезагрузки будильники восстанавливаются без запуска приложения. Как смотреть будильники: `adb shell dumpsys alarm | grep -A2 ReminderReceiver`.
- Не сделано: кнопки «Выполнено» и «Отложить» в уведомлении, показ напоминаний, пропущенных при выключенном телефоне, группировка уведомлений, настройка времени 09:00. Проверка на реальном телефоне.

## Перенос данных из старого приложения (сделан)
Нужно плавно перейти со старого ежедневника без потери данных. У пользователя есть резервная копия `.plnb` (изучена 22.10.2026). В репозиторий её не класть: там личные данные.
- Формат: zip, перед которым 8 лишних байт (архив начинается с `PK` на смещении 8). Внутри `Planner.db` (SQLite), `backup_meta` (JSON: `version`, `hash`), `photo/*.jpg|png`, `audio/*.aac`.
- Объём копии: около 8,6 тыс. задач (196 невыполненных, ~8,4 тыс. выполненных), ~17,7 тыс. подзадач, 17 категорий, 17 привычек (4 активные) и ~700 отметок привычек, 303 фото, 2 аудиозаписи.
- Нужные таблицы: `task`, `subTask`, `category`, `categoryInTask`, `regularity`, `habit`, `habit_record`, `implementation` (напоминания привычек), `habit_pause` (в копии пустая: пауза — флаг `habit.pause`, у всех 0), `photo`, `sound`, `sync_file` (имена файлов вложений). Служебные `sync_*` и `app_notifications_*` не нужны. Удалённые строки помечены `isRemoved = 1`, их не переносить.
- Задача: дата — `nextDate` (местная дата `2026-10-22`), время — `time` вида `H:m` (`16:0`), заметка — `text`, выполнена — `completed`. Приоритет `importanceType`: `not`/`small`/`medium`/`large` → нет/низкий/средний/высокий. Моменты (`created`, `completedDate`, `notifyDate`, `deadline`) — ISO в UTC; в копии местный пояс UTC+3, поэтому переводить в часовой пояс телефона. `notifyDate` — момент напоминания, `notifyInsistent` — настойчивое напоминание. `deadline` — отдельный срок «до», такого поля у нас нет.
- Повторы: каждое повторение — отдельная строка. `regularityUid` — не ссылка на серию, а код правила (`week_1_72_0` = тип_период_маска_двеНедели), общий для разных задач; серию узнаём по названию + правилу. В `regularity`: `type` (`day`/`week`/`month`), `period` (каждые N), `days` — байты с номерами дней (неделя: 1–7, при `byTwoWeeks` 1–14 на две недели; месяц: числа месяца), `daysMask` — те же дни битами. Наш `RepeatRule` не умеет разные дни на двухнедельный цикл и несколько чисел месяца.

## Память и батарея (замеры 25.10.2026)
Выпускная сборка 0.2 на эмуляторе (API 37) с искусственной копией размером с настоящую (8 626 задач, 23,8 тыс. подзадач, 17 категорий, 4 привычки по 120 отметок; генератор — Python со старой схемой, личных данных нет). На телефоне без USB замерить нельзя; там смотреть Настройки → Аккумулятор → расход по приложениям через день-два.
- Память (PSS): пустое приложение на главном — 34 МБ; с данными на главном — 39 МБ; «Выполненное» с подгрузкой до 100 строк — 46 МБ; поиск по всем задачам (все задачи с подзадачами в памяти) — 57 МБ, Java-куча 15 МБ; календарь — 59 МБ.
- Перенос копии такого размера: чтение ~4 с, запись ~10 с; память после — 41 МБ.
- Процессор: открытый главный экран в простое — 10 мс за минуту (лишних перерисовок нет); в фоне с выключенным экраном — 20 мс за 2 минуты, приложение заморожено системой в кэше; batterystats — 0,000012 мА·ч за 2 минуты.
- Фоновой работы нет: ни служб, ни WorkManager, ни периодических будильников, ни своих блокировок сна. Будильники — только на ближайшее напоминание каждой задачи и каждой привычки (`RTC_WAKEUP`), дата «сегодня» спит до полуночи и живёт только при открытом экране. Основной расход при пользовании — экран; тёмная тема на AMOLED-экране S21 FE экономит.

## Напоминания: на что обратить внимание
- На Android 13 и выше нужно разрешение на уведомления (`POST_NOTIFICATIONS`).
- Точные будильники требуют отдельного разрешения и ограничены системой; использовать их только там, где это действительно нужно.
- После перезагрузки телефона напоминания нужно перепланировать.
- Проверять на реальном устройстве, а не только в эмуляторе.
